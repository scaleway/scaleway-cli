- **Cloud-init from a file** — point k8s pools at a local cloud-init file instead of pasting YAML into a flag. [#6330](https://github.com/scaleway/scaleway-cli/pull/6330)
- **Kafka endpoints** — attach or detach a Kafka cluster to a private network with dedicated commands. [#6334](https://github.com/scaleway/scaleway-cli/pull/6334)

## Breaking changes and migrations

No action needed — the `instance` placement-group resource moved to the v2 API but keeps the same CLI surface.

## Autoscaling

### Group refresh

Roll out new group settings (instance type, strategy, …) immediately without deleting the group:

```sh
scw autoscaling group refresh group-id=<autoscaling-group-id>
```

## k8s

### Cloud-init and user data from a local file

Any k8s `user-data.*` argument now supports file loading with the `@` prefix, so you can keep your cloud-init config in a file instead of escaping it inline:

```sh
scw k8s pool create cluster-id=<cluster-id> name=workers node-type=DEV1-XL size=2 user-data.cloud-init=@cloud-init.yml
```

### Inline pool max termination grace period

Control how long deleting nodes are allowed to drain before the API forces deletion. This overrides the pod `PodDisruptionBudget` and `terminationGracePeriodSeconds`; the default is 15 minutes, up to 1 hour:

```sh
scw k8s cluster create ... max-termination-grace-period=1800
scw k8s pool update ... pools.0.max-termination-grace-period=600
```

## Kafka

### Endpoint create and delete

Instead of recreating the cluster, attach a Kafka cluster to a private network (or remove the endpoint) with explicit commands. Only `private_network` is supported for now.

```sh
scw kafka endpoint create <cluster-id> endpoint.private-network.private-network-id=<pn-id>
scw kafka endpoint delete <endpoint-id>
```

## MongoDB

### User creation

`scw mongodb user ...` now includes a create-user command against the v1 API:

```sh
scw mongodb user create instance-id=<instance-id> name=bob password=...
```

## RDB

### Connect snippets

`scw rdb config get` generates a ready-to-use snippet for your database client, so you stop hand-writing connection strings. Pick the language with `type=` and refine with `user=`, `db=` or `private-network=true`.

```sh
scw rdb config get <instance-id> type=node user=myuser db=mydb
scw rdb config get <instance-id> type=python private-network=true
```

## Search

### New resource types on the catalog

The `wofl` product joins the search catalog with its `wofl_run` and `wofl_definition` resource types, so `scw search` results and filters cover them.

## Bug fixes

- **instance**: filtering `scw instance server list state=...` with the stopped state failed because the CLI sent `stopped in place` instead of the snake_case `stopped_in_place` the API expects. It is now mapped correctly. [#6313](https://github.com/scaleway/scaleway-cli/pull/6313)
- **install**: the `scripts/get.sh` installer could pick the wrong archive when multiple assets shared an ambiguous file extension, breaking fresh installs on some platforms. [#6311](https://github.com/scaleway/scaleway-cli/pull/6311)
- **announce**: the new-release announcement message rendered with literal placeholders instead of the substituted values. [#6287](https://github.com/scaleway/scaleway-cli/pull/6287)
