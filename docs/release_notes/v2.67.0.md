## Audit trail

### Magic-link authentication events

Audit Trail now recognizes sign-ins done through a magic link (the passwordless email login). Authentication events for those sessions report the `magic_link` authentication method, and a failed magic-link attempt records `invalid_magic_link` as its failure reason — so security tooling can tell magic-link logins apart from password, passkey and SSO logins without guessing. The new values appear in the JSON output of the audit event listing:

```sh
scw audit-trail event list -o json
```

Look for `"method": "magic_link"` on sign-in events and `"failure_reason": "invalid_magic_link"` on the failed attempts.

## Bug fixes

- **mcp**: `scw mcp server serve` with `transport=streamable-http` bound its server to `:8080` on **all network interfaces**, exposing any AI agent pointed at the machine to a live CLI. The default address is now `localhost:8080`, so the server only listens on the loopback interface unless you pass an explicit `address=`.

```sh
scw mcp server serve transport=streamable-http
```

[#6839](https://github.com/scaleway/scaleway-cli/pull/6839) · [commit 2d6ba04](https://github.com/scaleway/scaleway-cli/commit/2d6ba04a4ec7c75c0d00b9b054ce41ab16807429)

- **mcp**: the MCP server registered tools that could **leak credentials** to the agent calling them. Commands that reveal the secret key (`scw info` with `show-secret=true`, `scw k8s kubeconfig get`, `scw k8s execcredentials`), forward it to a remote node over SSH (`scw k8s pool add-external-node`), drop into an interactive console (`scw instance server console`) or embed write tokens (`scw cockpit config get`) are now excluded from the tools the server exposes.
