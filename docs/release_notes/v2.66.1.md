## Highlights

- **Delete a project with its resources** — tear down a Project and everything it contains in one command. [#6825](https://github.com/scaleway/scaleway-cli/pull/6825)
- **Customer-managed keys on more databases** — encrypt RDB instances and Data Warehouse deployments at rest with a Key Manager key. [#6769](https://github.com/scaleway/scaleway-cli/pull/6769) [#6807](https://github.com/scaleway/scaleway-cli/pull/6807)

## Breaking changes and migrations

No action needed — the instance `volume` and `snapshot` resources moved to the v2 API with an unchanged CLI surface.

## Account

### Project cleanup

`scw account project` gains a `delete-with-resources` verb that deletes a project **along with all the resources it contains** — no more draining projects resource by resource before removal:

```sh
scw account project delete-with-resources <project-id>
```

## Data Warehouse

### Deployment encryption at rest

Data Warehouse deployments accept a `kms-key-id` to encrypt data at rest. The key must be enabled and use symmetric encryption, and this can only be chosen at creation time:

```sh
scw datawarehouse deployment create ... kms-key-id=<kms-key-id>
```

## Instance

### Volume and snapshot on the v2 API

The instance `volume` and `snapshot` resources moved to the v2 API (continuing the migration started in v2.66.0); the CLI surface is unchanged (see [Breaking changes](#breaking-changes-and-migrations)).

## RDB

### Instance encryption at rest

You can now pass `encryption.kms-key-id` when creating an RDB Database Instance to encrypt it with a Key Manager key:

```sh
scw rdb instance create ... encryption.kms-key-id=<kms-key-id>
```

## Bug fixes

- **core**: some terminal rendering could **panic with a negative `strings.Repeat` count** on certain outputs; the renderer now guards against it. [#6801](https://github.com/scaleway/scaleway-cli/pull/6801)
