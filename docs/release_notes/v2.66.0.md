## Highlights

- **DNS record import** — import a zone's records in bulk from BIND or JSON files. [#5470](https://github.com/scaleway/scaleway-cli/pull/5470)
- **k8s pools on a private network** — worker pools attach to a private network at creation time. [#6524](https://github.com/scaleway/scaleway-cli/pull/6524)
- **Object Storage custom S3 endpoint** — point bucket commands at any S3-compatible endpoint, gateway or proxy. [#5636](https://github.com/scaleway/scaleway-cli/pull/5636)
- **Cockpit from any resource** — open the Grafana dashboard of a server, cluster, database and more in one command. [#6512](https://github.com/scaleway/scaleway-cli/pull/6512)
- **Instance IP lookup filters** — find free IPs or a server's IPs server-side instead of filtering locally. [#6536](https://github.com/scaleway/scaleway-cli/pull/6536)

## Breaking changes and migrations

- **instance**: the `private-nic` resource was renamed to **`private-network-interface`** on the v2 API — update scripts that call `scw instance private-nic ...`. [#6157](https://github.com/scaleway/scaleway-cli/pull/6157)
- **instance**: user-data, security-group, server-type, volumes and snapshots also moved to the **v2 API** (mostly transparent; a few verbs were aligned, e.g. server-type listing).
- **annotations**: **batch-delete endpoints are deprecated** — update tooling that bulk-deletes annotations. [#6747](https://github.com/scaleway/scaleway-cli/pull/6747)
- **messageq**: volume-create requests no longer send an unrequested `deployment-id` field, which the API rejected. [#6579](https://github.com/scaleway/scaleway-cli/pull/6579)

## Annotations

### Audit trail annotations

The `annotations` namespace now exposes **audit trail annotations** for storing structured metadata on resources and events.

## Audit trail

- Event **visualization** is improved, so trails are easier to scan.
- Trails report **Kafka cluster** connection info, so streaming monitoring has the details it needs.

## Autocomplete

- Completions understand the active **`--profile`** flag and read the right profile's config.
- **Descriptions** of commands and arguments are shown in completion menus where the shell supports it.
- Required args already typed (e.g. `instance-id`) are forwarded to the *list* command that powers value completion, so `name=` only completes values valid for that parent resource.
- When `SHELL` is unset, the installer defaults to `/bin/bash` instead of misbehaving.
- Completion scripts use the **actual binary name as basename** (e.g. `scw-dev`), so installed or renamed binaries get matching completions.

## Autoscaling

### Milan zones

Autoscaling groups can run in the new Milan zones **`it-mil-1`, `it-mil-2`, `it-mil-3`**. Specify them with `zone=` or set one as your default zone.

## Baremetal

### Commitments

New sub-commands to view and manage server commitments, and server reservations now accept a commitment period:

```sh
scw baremetal commitment list
scw baremetal server create ... reservation-period=one_year
```

## Billing

### Charge list visualization

`scw billing charge list` now renders charges in a clearer, aggregated layout so you can read your bill at a glance.

## Cockpit

### Open a resource in Cockpit

Almost every resource command now has a `cockpit` verb that opens the resource's Grafana dashboard in your browser — no more hunting through the console:

```sh
scw k8s cluster cockpit <cluster-id>
scw instance server cockpit <server-id>
```

### Datasource rate limits

Datasources now support **ingestion rate limits** per metric, log or trace stream, so you can protect your project from runaway ingestion:

```sh
scw cockpit datasource create ... metrics-limits.ingestion-rate-limit-samples-per-second=10000
```

## Data Orchestrator

The `data_orchestrator` namespace is now activated in the CLI.

## Dataviz

The `dataviz` (dashboards and analytics) namespace is now activated in the CLI.

## DNS

### Record import

Bulk-add records to a zone from a zone file, instead of scripting per-record `scw dns record add` calls. Supported formats are BIND zone files and JSON; `replace=true` clears the zone's existing records first.

```sh
scw dns record import my-domain.tld content=@./zone.txt
scw dns record import my-domain.tld content=@./records.json format=json replace=true
```

## File

### Filesystem from snapshot

Filesystems can now be created from an existing **snapshot** instead of only from an empty block, letting you restore data quickly:

```sh
scw file filesystem create from-snapshot.snapshot-id=<snapshot-id> from-snapshot.size=1GB
```

## Instance

### IP lookup filters

`scw instance ip list` filters by associated `server` and/or `detached` status, so you can find free IPs or a server's IPs without client-side filtering:

```sh
scw instance ip list detached=true
scw instance ip list server=<server-id>
```

### Security groups on private-network interfaces

Security groups can now be attached to **private-network interfaces** (`scw instance private-network-interface`), extending the same protection you had on public NICs to private traffic.

### New Milan zones

New Milan (Italy) zones are supported: **`it-mil-1`, `it-mil-2`, `it-mil-3`** (Block zones shipped in v2.65.2).

### v2 API resources

Several instance resources moved to the v2 API: `private-nic` → **`private-network-interface`**, plus security-group, server-type, user-data, and code-generated **volumes and snapshots** (see [Breaking changes](#breaking-changes-and-migrations)).

## Interlink

### Dedicated connections

For self-hosted and hybrid setups, Interlink dedicated-connection commands are now exposed: query a specific physical connection or list your connections in a region.

```sh
scw interlink connection get <connection-id>
scw interlink connection list region=fr-par
```

## IPAM

### Load Balancer IPs

IPAM now tracks a new `lb_ip` resource type, so Load Balancer IPs show up in `scw ipam ip list` and filters.

## k8s

### Pool private network

K8s pools can be attached to a private network, so worker nodes join that network at pool creation time:

```sh
scw k8s cluster create ... pools.0.private-network-id=<pn-id>
scw k8s pool create cluster-id=<cluster-id> name=workers node-type=DEV1-XL size=2 private-network-id=<pn-id>
```

## Kafka

### Volume resize

`scw kafka cluster update` accepts `volume-size-bytes` to grow the per-broker storage volume (increase only).

## Object Storage

### Custom S3 endpoint

Bucket commands (`cp`, `rm`, `sync`, ...) accept a custom S3 endpoint — useful for S3-compatible gateways, proxies or migration tooling:

```sh
scw object bucket cp ./data s3://my-bucket s3-endpoint=https://gateway.example.com s3-use-path-style=true
```

A custom endpoint overrides any region passed for the bucket.

## Redis

### Cluster connect

`scw redis cluster connect` now shares the same `connect` pipeline as other products (kubeconfig-style local connection), so connecting to a Redis cluster behaves like the rest of the CLI.

## Search

### kvdb resource types

The search catalog gains the `kvdb` resource types, so crypto-key-value stores appear in `scw search` results and filters.

## Webhosting

### Database name and username rules

The webhosting database name and username requirements were updated to match the API, so `scw webhosting database create` validates input upfront instead of failing server-side.

## Bug fixes

- **baremetal**: a server-option type was missing its option type, which could produce **malformed requests** and broken help output. [#6765](https://github.com/scaleway/scaleway-cli/pull/6765)
- **autocomplete**: completion file names used a hard-coded `scw` instead of the actual binary basename, breaking completions for renamed binaries (see [Autocomplete](#autocomplete)). [#6569](https://github.com/scaleway/scaleway-cli/pull/6569)
- **autocomplete**: the completion installer crashed or misbehaved when `$SHELL` was empty; it now defaults to `/bin/bash` (see [Autocomplete](#autocomplete)). [#6661](https://github.com/scaleway/scaleway-cli/pull/6661)
- **autocomplete**: required args were not forwarded to the completion's backing list command, so `name=` suggestions ignored the parent resource (see [Autocomplete](#autocomplete)). [#6571](https://github.com/scaleway/scaleway-cli/pull/6571)
- **core**: commands defined without argument specs could **fail at generation or execution time with an unclear error**; a guard now reports them clearly. [#6617](https://github.com/scaleway/scaleway-cli/pull/6617)
- **messageq**: removed an unrequested `deployment-id` being sent on volume-create requests (see [Breaking changes](#breaking-changes-and-migrations)). [#6579](https://github.com/scaleway/scaleway-cli/pull/6579)
